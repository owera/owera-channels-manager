## ch2 Rodrigo Recio (PT-BR)

### 1. TabNews — post
**Título:** Seu modelo local “não fala português”. Quase nunca é o modelo.
**Corpo:**
Você baixa um 7B/13B Q4, pergunta em PT-BR, e a resposta vem manca, misturada com inglês, ou inventando concordância. A conclusão imediata é “esse peso é ruim”. Às vezes é. Na maioria das vezes o vilão é o prompt + o template + o `num_ctx` que o runtime escolheu sem te avisar.

Teste honesto, mesmo peso, mesmo quant: (1) system prompt em PT-BR explícito, (2) chat template do modelo, não o genérico, (3) contexto real vs o default de 4k. Se o (1)+(2) resolve e o quant não mudou, você não precisava de um 27B.

Short com o recorte:
https://youtu.be/82uSCYDB9fA

Se você roda local em PT: mesmo prompt, template nativo vs genérico. Número de tokens válidos em português vale mais que mais um “troca o modelo”.

### 2. r/brdev — post/comment
**Título / ângulo:** Modelo local demora 30s. A culpa quase nunca é a rede.
**Corpo:**
Pergunta sincera: você mediu o tempo até o *primeiro token* ou o tempo até a resposta inteira?

Cold load (peso saindo do SSD/VRAM) e decode (tokens/s) são contas diferentes. 30s com GPU “ocupada” no `nvidia-smi` costuma ser load, não inferência. Keep-alive / o processo que *não* morre é o que mata os 30s. Trocar de modelo sem medir os dois números é chute.

Short com o recorte:
https://youtu.be/DXYRen7aFTw

Alguém tem o par load vs decode no mesmo 7B Q4, nativo vs Docker? Quero os dois números.
