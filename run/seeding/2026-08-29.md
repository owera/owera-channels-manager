## ch2 Rodrigo Recio (PT-BR)

### 1. TabNews — post
**Título:** O modelo roda no Linux e trava no Windows. Quase nunca é o peso.
**Corpo:**
Mesmo GGUF, mesma quant, mesma VRAM. No Linux gera. No Windows trava no load ou cai pra CPU. O que muda não é o modelo — é o runtime: driver, DirectML vs CUDA, path com acento, antivirus indexando o blob, `num_gpu` que o Ollama no Windows ignora.

Teste mínimo antes de formatar o PC: o mesmo arquivo `.gguf` no llama.cpp dos dois lados, com o mesmo `-ngl`. Se um lado splilla e o outro não, você não precisa de placa nova.

https://youtu.be/PmhlkQBz6Eg

Quem já viu o mesmo Q4_K_M “caber” no Linux e OOM no Windows, o vilão foi driver ou foi o backend?

### 2. r/brdev — post/comment
**Título / ângulo:** GPU no slot errado da placa-mãe (x4 em vez de x16) parece “modelo lento”.
**Corpo:**
Você mede tok/s baixo, culpa o GGUF, compra placa maior — e o PCIe 3.0 x4 do slot de baixo estava comendo a banda de pesos. O modelo cabe na VRAM. O bus não alimenta.

Olhe no GPU-Z / `nvidia-smi -q` o PCIe current link width antes de abrir o Mercado Livre.

Short de ontem (t4):
https://youtu.be/E8yw1kSt45c

No seu setup, o slot “de baixo” já te comeu quantos tok/s?
