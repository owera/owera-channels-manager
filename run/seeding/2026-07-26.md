## ch2 Rodrigo Recio (PT-BR)

### 1. TabNews — post
**Título:** Acurácia de 95% e o modelo é inútil: a métrica que engana todo mundo em produção
**Corpo:**
Todo mundo aprende acurácia primeiro e é exatamente ela que mais engana em produção. Num
dataset com 5% de fraude, um modelo que responde "não é fraude" pra tudo tem 95% de acurácia
e zero utilidade. O que importa é o par precisão/recall — e qual dos dois erros custa mais
caro no SEU caso: falso positivo (bloquear cliente bom) ou falso negativo (deixar fraude
passar). Essa escolha é de negócio, não de ML, e quase nenhum time formaliza isso antes de
treinar.

Fiz um vídeo curto explicando com exemplos concretos de produção:
https://youtu.be/oDS7JsyMFJk

Como vocês definem o threshold em produção — otimizam F1 cegamente ou custam os dois erros
separadamente? Curioso com o que o mercado BR realmente faz.

### 2. r/brdev — comment (achar thread fresca sobre "IA local" / "GPU" / "out of memory")
**Draft:**
O erro clássico do OOM em placa de 24GB: o modelo cabe, mas o KV-cache do contexto não —
ele cresce linear com o tamanho do prompt e em fp16 come gigabytes sem aparecer em nenhum
lugar óbvio. Regra prática que me salvou: dimensione VRAM pela soma pesos + KV-cache no
contexto MÁXIMO que você vai usar, não pelo tamanho do arquivo. Expliquei a conta num short
de 40s (https://youtu.be/b2jrHK2Mt5Y), mas a regra funciona sem clicar: contexto de 32k em
modelo 7B fp16 ≈ mais de 8GB só de cache.

## ch1 Owera Software (EN)

### 1. dev.to — post
**Title:** I built the same RAG pipeline in LangChain and CrewAI — here's where each one broke
**Body:**
Comparisons between agent frameworks are usually feature-table listicles written from the
docs. I wanted the boring truth, so I built the same production-shaped RAG system twice —
same retriever, same reranker, same eval set — once in LangChain, once in CrewAI.

Short version: LangChain won on retrieval control (custom rerank step is first-class),
CrewAI won on multi-agent ergonomics but fought me on fine-grained pipeline control, and
the token bills diverged way more than I expected under retry storms.

Full walkthrough (14 min): https://youtu.be/uG_chjI6NLs
Happy to share the eval harness if anyone wants to reproduce the numbers.

### 2. r/LangChain — comment (find a fresh "LangChain vs CrewAI / which framework" thread)
**Draft:**
Having built the same RAG system in both this month: the decision collapses to one question
— do you need fine-grained control of the retrieval pipeline (rerankers, custom scoring,
context compression)? LangChain gives you that as first-class primitives; CrewAI is nicer
for role-based multi-agent flows but you end up fighting it for pipeline control. Cost
surprise nobody mentions: their retry behavior under flaky tool calls produces very
different token bills (I measured it here if useful: https://youtu.be/h6xcDxszM3w).

### 3. Comment draft — adjacent channel (recent video on LangGraph / agent state)
Great breakdown. One production gotcha worth adding: LangGraph checkpoints can corrupt
under concurrent users if you share a checkpointer across sessions without namespacing
thread_ids — the symptom is agents "remembering" another user's state, which looks like a
model bug but is a persistence bug. Hit this in prod last month; short repro here if
useful: https://youtu.be/p_A33_4s__o
