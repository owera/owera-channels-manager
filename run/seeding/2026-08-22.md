## ch2 Rodrigo Recio (PT-BR)

### 1. TabNews — post
**Título:** Seu modelo “demora 3 segundos”. Quase nunca é a GPU.
**Corpo:**
Você abre o chat local, pergunta, e o relógio anda 2–3s antes do primeiro token. A reação é comprar GPU. Às vezes é VRAM. Na maioria das vezes o 3s é: (1) cold load do peso, (2) KV cache no default de 4k quando o modelo anuncia 128k/1M, (3) o runtime que mata o processo e recarrega a cada prompt.

Teste honesto, mesmo peso, mesmo quant: keep-alive ligado, `num_ctx` explícito, e o tempo até o *primeiro* token vs o tempo até a resposta inteira. Se o (1) caiu e o decode não mudou, você não precisava de uma 4090.

Long de ontem:
https://youtu.be/Qfy-uufoNKQ

Se você roda Ollama: o `num_ctx` no Modelfile é o que você acha, ou o default de 4k?

**Título / ângulo:** GPU dedicada no notebook e o modelo ainda usa o iGPU.
**Corpo:**

No Windows, o driver “auto” e o runtime que não pinou o device mandam o 7B pro iGPU e a dedicada fica a 0%. O arquivo cabe. A placa existe. O processo não está nela.

### 3. LinkedIn (PT) — post curto
**Corpo:**
DDR4 barata não é “memória demais”. É o CPU segurando o KV cache quando a VRAM já encheu.

O modelo cabe. A inferência anda. Aí o contexto cresce, parte do cache vaza pra RAM, e os tokens/s caem no piso da DDR. Não é o peso. É o spill.

Short:
https://youtu.be/IuB_OhXzLV8

Se você roda 24GB: mediu tokens/s em 4k vs 16k no mesmo Q4, ou só olhou se “cabe”?

**Title:** JSON mode still returns malformed objects. The flag is not a parser.
