## ch2 Rodrigo Recio (PT-BR)

### 1. TabNews — post
**Título:** Docker come VRAM e o `nvidia-smi` não te avisa do jeito que você pensa
**Corpo:**
Você sobe o Ollama (ou o vLLM) num container, vê a GPU “ocupada”, e assume que o modelo está sozinho na placa. Não está. O runtime do Docker, o driver, e às vezes um segundo processo no host já comeram um pedaço. O que resta não é “24GB”. É 24GB menos o que o daemon não devolveu.

Teste honesto: o mesmo modelo, o mesmo quant, o mesmo `num_ctx` — nativo vs container. Se o nativo cabe e o container OOM, o vilão não é o GGUF. É o orçamento que você não mediu.

Short com o recorte:
https://youtu.be/xUld81Ay3Vc

Se você roda local em Docker: VRAM nativo vs VRAM no container, mesmo prompt. Número real vale mais que mais um “minha 4090 não aguenta”.

### 2. r/brdev — post/comment
**Título / ângulo:** Você fecha o Ollama e o modelo some. Isso não é “feature”, é o default te sabotando.
**Corpo:**
Pergunta sincera: quantas vezes você reabriu o chat, esperou o reload de 8–20s, e achou que a GPU “esquentou”?

Ollama descarrega o modelo quando o processo some. Fechar o app ≠ manter o peso na VRAM. Keep-alive / daemon / o processo que *não* morre é o que segura o modelo. Reload não é “IA lenta”. É frio de novo.

Short com o recorte:
https://youtu.be/wzy6rtICj4k

Alguém mediu o tempo de reload vs o tempo de decode no mesmo 7B Q4? Quero os dois números, não a opinião.

### 3. LinkedIn (PT) — post curto
**Corpo:**
Autoscaling de GPU quase nunca quebra no “faltou réplica”. Quebra na conta: quantas cópias do modelo você realmente precisa quando o QPS real é 2 e o cold load é 40s?

Antes de `replicas=N`, mede: tempo de load, QPS de verdade, e quanto da GPU fica em 0% entre requests. Sem esses três, “produção” é um multiplicador de invoice.

Long:
https://youtu.be/jjWBlO3GdAQ

Se você opera modelo em GPU: load time + QPS + % idle. Sem isso, réplica é chute.
