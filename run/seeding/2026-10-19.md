### 1. r/LocalLLaMA — comment on a fresh thread about MCP / Claude Code tool load
A plugin manifest that runs a shell before the tool is registered is not a setup step. It is code execution you did not invoke, on the machine that holds the tokens. If the manifest can spawn a process at load, treat it like a postinstall script: read it before you enable the plugin.

Short I cut on that failure (my channel): https://www.youtube.com/shorts/_M1y7vw7Qyo

### 2. dev.to — post
**Title:** Your plugin ran a shell before the tool existed

**Body:**
The failure mode is quiet. The host loads the plugin, the manifest starts a process, and only then does the tool show up in the list. By the time you approve the first call, the shell already ran.

Read the manifest the way you read a postinstall. If load can exec, enable is consent.

https://www.youtube.com/shorts/_M1y7vw7Qyo
